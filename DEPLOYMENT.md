# Deploying AUSTPC to Render + MongoDB Atlas

The whole site runs as **one Render web service**: the Express backend serves the
API *and* the built React app, so there is no separate frontend host and no CORS
setup to get wrong.

Everything in the repository is ready. What remains needs your accounts, so the
steps below are the ones only you can do. Budget about 20 minutes.

| | |
|---|---|
| **Cost** | $0 — Render free plan + MongoDB Atlas free tier (M0) |
| **You need** | Your GitHub repo, a [Render](https://render.com) account, a [MongoDB Atlas](https://www.mongodb.com/cloud/atlas/register) account |
| **Result** | `https://austpc.onrender.com` (or your own domain) |

---

## Step 1 — Create the database (MongoDB Atlas)

1. Sign up / log in at <https://cloud.mongodb.com>.
2. **Create a cluster** → choose **M0 (Free)**. For region pick **AWS / Singapore
   (ap-southeast-1)** or **Mumbai (ap-south-1)** — both are close to Bangladesh.
3. **Database Access** → *Add New Database User*:
   - Authentication: Password
   - Username: `austpc` (or anything)
   - Password: click **Autogenerate** and **copy it somewhere safe**
   - Role: *Read and write to any database*
4. **Network Access** → *Add IP Address* → **Allow access from anywhere
   (`0.0.0.0/0`)**.
   Render's free plan does not give your service a fixed outbound IP, so a
   narrower allowlist would break the connection. Your database user's password
   is what protects the cluster — which is why it must be a strong generated one.
5. **Clusters → Connect → Drivers** and copy the connection string. It looks like:

   ```
   mongodb+srv://austpc:<db_password>@cluster0.ab12cde.mongodb.net/?retryWrites=true&w=majority
   ```

6. Edit that string before using it:
   - replace `<db_password>` with the real password
   - insert the database name `austpc` **before** the `?`

   Final form:

   ```
   mongodb+srv://austpc:REALPASSWORD@cluster0.ab12cde.mongodb.net/austpc?retryWrites=true&w=majority
   ```

   > If your password contains `@ : / ? # [ ] %`, percent-encode it
   > (`@` → `%40`, `#` → `%23`, …) or the connection string won't parse.

**You do not need to seed the database.** On its first request the backend
detects an empty database and inserts the default site content automatically
(verified against an empty cluster). You can edit everything afterwards from the
admin panel.

## Step 2 — Choose your admin password

Pick a real password (not the local dev default) and turn it into a SHA-256 hash —
the server only ever stores the hash:

```powershell
node -e "console.log(require('crypto').createHash('sha256').update('YOUR_NEW_PASSWORD').digest('hex'))"
```

Copy the 64-character output. Keep the plain password for logging in.

---

## Step 3 — Push the code to GitHub

From the repository root, commit everything and push to the repo you already have:

```powershell
git add .
git commit -m "Add backend, database, and Render deployment config"
git push
```

`Backend/.env`, `Backend/data/`, `Backend/uploads/`, and `node_modules/` are
git-ignored — your local secrets are not published.

---

## Step 4 — Create the Render service

1. Go to <https://dashboard.render.com> → **New +** → **Blueprint**.
2. Connect your GitHub account and select this repository.
3. Render reads [`render.yaml`](render.yaml) and proposes a web service named
   **austpc**. Click **Apply**.
4. It will prompt for the variables marked `sync: false`. Fill in:

| Variable | Value |
|---|---|
| `MONGODB_URI` | the full Atlas string from Step 1 |
| `ADMIN_USERNAME` | e.g. `austpc_admin` |
| `ADMIN_PASSWORD_HASH` | the 64-char hash from Step 2 |
| `CLIENT_ORIGIN` | leave blank for now (Step 6) |
| `PUBLIC_BASE_URL` | leave blank for now (Step 6) |
| `AWS_*`, `S3_*` | leave blank for now (Step 7) |

`ADMIN_TOKEN_SECRET` is generated by Render automatically — don't set it yourself.

The first build takes ~3–5 minutes (it installs both projects and builds the
React bundle). Watch the **Logs** tab; a healthy start ends with:

```
[db] MongoDB connected
[db] indexes synced (sitecontents, images, applications)
[server] running on http://localhost:10000 (production)
```

## Step 5 — Check that it works

Open your Render URL (shown at the top of the service page, e.g.
`https://austpc.onrender.com`):

- the homepage loads with hero images and seeded content
- `/api/health` returns `{"status":"ok","database":"connected"}`
- `/admin` accepts your username and new password
- refresh the page while on `/events` — it should still work, not 404

---

## Step 6 — Fill in the two URL variables

Now that you know the real URL, go to **Environment** in the Render dashboard and set:

| Variable | Value |
|---|---|
| `CLIENT_ORIGIN` | `https://austpc.onrender.com` |
| `PUBLIC_BASE_URL` | `https://austpc.onrender.com` |

Save — Render redeploys automatically. (The site works before this; these matter
for correct upload URLs and if you ever host the frontend separately.)

## Step 7 — Permanent image storage ⚠️

**This one genuinely matters.** Render's free plan has an **ephemeral
filesystem**: any image uploaded through the admin panel is stored on disk and
**will be deleted** on the next deploy, restart, or wake-from-sleep. Text content
is safe — it lives in Atlas — but uploaded photos would vanish.

Two ways to fix it:

**A. Cloudflare R2 (free, recommended).** 10 GB free, S3-compatible, no egress
fees. The backend already supports it.

1. Cloudflare dashboard → **R2** → create a bucket, e.g. `austpc-uploads`.
2. Under the bucket → **Settings** → enable **Public access** (so image URLs load
   in browsers), and note the public bucket URL.
3. **R2 → Manage API Tokens** → create a token with *Object Read & Write*. Copy
   the Access Key ID and Secret.
4. In Render → **Environment**, set:

   | Variable | Value |
   |---|---|
   | `STORAGE_DRIVER` | `s3` |
   | `AWS_ACCESS_KEY_ID` | R2 access key id |
   | `AWS_SECRET_ACCESS_KEY` | R2 secret |
   | `S3_BUCKET_NAME` | `austpc-uploads` |
   | `S3_ENDPOINT` | `https://<ACCOUNT_ID>.r2.cloudflarestorage.com` |
   | `S3_FORCE_PATH_STYLE` | `true` |
   | `AWS_REGION` | `auto` |

**B. Skip uploads.** Paste image URLs into the admin panel instead of uploading
files — every image field accepts a plain URL. Nothing to configure.

Either way the rest of the site is unaffected.

## Free-plan limitations to expect

- **Cold starts.** A free service sleeps after ~15 minutes of no traffic; the
  next visitor waits ~30–50 seconds. Upgrading to Render's Starter plan
  (~$7/month) removes this. A cron pinger is against Render's free-tier terms.
- **Atlas M0** gives 512 MB — thousands of events, members, and applications.
- **Build minutes** are limited but generous for a site that deploys occasionally.

## Using your own domain

1. Render service → **Settings → Custom Domains → Add**, enter e.g. `austpc.com`.
2. Add the CNAME/A records Render shows to your DNS provider.
3. TLS is issued automatically once DNS propagates.
4. Update `CLIENT_ORIGIN` and `PUBLIC_BASE_URL` to the new domain.

## Troubleshooting

| Symptom | Cause and fix |
|---|---|
| Deploy fails, `vite: not found` | `npm ci` skipped devDependencies. The build command in `render.yaml` already passes `--include=dev` for the Frontend — make sure it wasn't edited. |
| Logs show `MongooseServerSelectionError` | Atlas Network Access doesn't allow `0.0.0.0/0`, or the password in `MONGODB_URI` is wrong / not percent-encoded. |
| Server exits with `Refusing to start in production` | `ADMIN_PASSWORD_HASH` or `ADMIN_TOKEN_SECRET` is missing. This guard is deliberate — set them in Render's Environment tab. |
| Site loads but admin login fails | The hash must be of your new password, generated with the exact command in Step 2 (no trailing spaces or newline). |
| Uploaded images disappear after a while | Expected on the free plan — see Step 7. |
| Page 404s on refresh at `/events` | The SPA fallback is disabled; confirm `SERVE_FRONTEND=true` is set. |
| Homepage loads but has no images/styling | Check the browser console for CSP errors and open an issue — the policy is defined in `Backend/app.js`. |
